# 能保留原始拍摄时间的视频压缩脚本

使用手机相册压缩的时候常常会遇到一个问题，压缩完的视频的拍摄时间会变成压缩的那个时间，于是导致这个视频在相册里显示的位置就直接乱套了……

于是我便 vibe coding 了这样的一套脚本，能在压缩视频之后将原片拍摄时间写回新文件。（当然其实在写这个脚本之前我先让它写了一个能修改视频拍摄时间的脚本，写完之后突然意识到让它把一整套流程包下来岂不是更方便？）

画质压缩方案采用的是：**x265 编码器 + HEVC 格式 + medium 预设 + CRF 控制**。

经 ai 多次对照压缩分析和我的肉眼对比，这种算法确实比我小米手机相册压缩之后的画质（在差不多的视频大小下）会更好。

## 启动

Windows 上安装 Node.js，并确保 `node` 在 PATH 中，然后双击 `启动.bat`。
浏览器会打开 [http://localhost:4319](http://localhost:4319)。当前电脑已具备运行环境，无需安装 npm 依赖。

FFmpeg 和 ExifTool 随目录提供，移动工具时请保留这两个子目录。
若服务已经运行，可直接打开网页；正常通过启动脚本启动时，关闭服务窗口即可停止服务。

## 使用

- 添加视频或文件夹，点击左侧文件查看和调整参数。
- 每个视频独立设置 CRF 和 faststart；faststart 默认关闭。
- 两个“应用到全部”按钮分别复制当前 CRF 或 faststart 开关。
- 导入后自动快速粗估各档大小；画质标签是经验参考，最终大小和观感以输出为准。
- 输出默认添加 `_compressed` 后缀，原片保留；完成后写回拍摄时间。

## 文件

- `server.mjs`：本地服务、编码任务和拍摄时间恢复。
- `quick-estimate.mjs`：快速体积粗估与缓存。
- `public/`：网页界面。
- `ffmpeg/`、`exiftool/`：随附的运行工具。

此仓库保留随附工具，便于本地恢复完整工作版本。视频、临时文件、运行日志和本地实验目录不纳入 Git。

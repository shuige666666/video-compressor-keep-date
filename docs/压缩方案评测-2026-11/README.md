## 用户人工复审结论与实际决策

以下是本项目使用者在电脑放大仔细对比、并结合正常观看条件后给出的主观判断；没有将其冒充双盲或多人观看实验。

- **x265 medium 与 fast 非常接近**。fast 偶尔在局部明显变差，也有少数位置优于 medium；总体差异很小，可以接受，因此把 fast 改为默认，medium 留作个别重要或异常片段的备选。
- **NVENC p7 的部分细节与噪点表现较差**。本次复审中，放大仔细看时，使用者更偏好相近大小的 x265 medium/fast；提高 NVENC 码率也没有改变使用者的整体偏好。正常大小观看时几种方案很接近，手机上差异更不明显。用户仍优先追求画质，因此暂不开发 NVENC 选项。
- **手机相册的观感可以接受，主观上优于本轮 NVENC p7**。压缩速度特别快，使用者报告完整视频大多10秒或以内完成；压缩比例较集中，但会改写拍摄时间，因此采用“手机快压 + PC按原片恢复时间”的备用流程。
- **只切换预设，不自动降低CRF一档**。fast 21 在少量补测中以多约9%—12%体积取得接近 medium 22 的指标，但人工复审并不要求默认付出这部分体积。生产 CRF 默认25是产品选择，本轮主体实测档位是22/24，不能把25档称为同样全面实测过。

这些结论只针对本轮素材、设备、设置和使用者的观看偏好，不推广到所有手机、所有 NVENC 配置或所有视频。

## 自动指标支持到什么程度

主体是六段 × medium/fast CRF22/24 与两档 NVENC p7，共36个版本；扩展8个版本，总计44。另有六个手机完整版本、一个独立复核片段的3个版本，以及4次重复测速。

把 CRF22 和24的12组比较全部纳入后：

|比较|编码速度倍数|VMAF平均分差|
|---|---|---|
|fast / 同CRF medium|1.33—2.03倍，中位 1.66倍|fast 低 0.25—0.77 分|
|NVENC p7 / 相近体积 medium|3.37—6.87倍|NVENC 低 1.15—3.00 分|

VMAF 分差不是画质损失百分比，也不是肉眼可见阈值。手机与PC没有全部对齐码率，不能直接根据表中分数确定同体积效率的统一排名。原始历史报告有些摘要只取CRF22，本页统计包含22与24。

p5/p7仅在C1、C6补测，VMAF差约0.05—0.09；不能因此认为所有场景都没有差异。fast 21接近medium 22的趋势有C1、C6和额外复核片段支持，但没有对所有场景完成相近画质搜索。高码率NVENC也只在C3、C5补测，没有测出通用的“追平画质所需体积”公式。

## 关键方法与正确性

1. 输出保持原分辨率、位深和显示几何，音频优先复制；关闭faststart，不添加降噪、锐化或针对指标的tune。预设和CRF之外的设置尽量对齐。约1秒GOP沿用当时生产脚本，但各编码器场景切换插入的I帧数量并不完全相同。
2. 使用 `-fps_mode:v:0 passthrough -enc_time_base:v:0 -1`；44个正式版本的记录均通过帧数和逐帧相对时间戳核对。评分中重新对齐帧序号不替代输出时间轴检查。手机六段的全片帧数与相对PTS也一致。
3. NVENC使用 `p7/p5 + hq + vbr + fullres multipass + lookahead32 + spatial/temporal AQ + bf3`，并按实际输出校准码率。**关闭参考B帧，但保留3个B帧**后，本机这套组合通过VFR检查。参考B帧的部分配置曾出现时间戳偏差；不能解释为所有NVENC都必须关闭B帧或始终无法保持VFR。
4. 手机标记是BT.601系列，原片是BT.709。保留直接YUV及601→709矩阵归一化两组指标，截图也保留过两种解释。不能简单认定全部错标，也不能选更高VMAF就宣布颜色正确。详情见色彩口径文档。
5. 音轨检查曾比较前3秒PCM；这不是整段逐包或完整音画同步证明。字幕、HDR、10-bit等未覆盖内容不作保证。

## 数字口径与旧结论修正

- 主对照表的MB为十进制，大小统一为**同选区视频轨载荷**，不含音频、元数据和封装。原片和手机选区按显示顺序映射样本；PC选区文件取完整视频轨。手机完整文件大小另列。
- `summary.json`和原CSV中的`sizeMB`是**完整PC输出文件**大小，不能与视频轨MB混用；原CSV的`sizeRatio`还是早期“输出文件 / 原选区视频轨”的混合口径。统一视频轨对视频轨比例以新对照表、`segment-sizes.json`及`phone.json`为准。极少量元数据写回造成的字节差不解释为压缩效率变化。
- 手机速度是使用者报告的整体范围，没有逐片独立计时，且手机压的是完整视频，PC计时多为10秒选区，因此不能直接计算精确加速倍数。
- **小文件不等于压得过狠**。CRF并不保证固定压缩比例，也不能按某段占原片的比例直接判定画质。
- **不把NVENC一概归类为“不适合存档”**。它是否合适取决于目标、设置与人工观感；本项目选择暂不使用是使用者在本轮对照后的取舍。
- 速度会受温度、供电和顺序影响。C6某次CRF24比22更慢，不能解释为提高CRF使编码变慢。重复测速记录已保留。

## 清理实验目录后的使用

本目录的Markdown、结构化指标、完整命令记录、截图计划和脚本快照均已独立保存。旧实验目录可从阅读及数字审计流程中移除。**本归档不包含原视频、编码输出或截图像素**：删掉实验目录后，无法仅凭这些文档重新观看当时的压缩片或图片。
